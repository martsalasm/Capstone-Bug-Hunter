## ¿De qué trata el proyecto?

**Bug-Hunter** es una plataforma orientada a estudiantes de DUOC UC que buscan adquirir experiencia práctica en el desarrollo de software mediante la colaboración en proyectos de programación, sin necesidad de comprometerse con trabajos extensos o de larga duración.

La plataforma permitirá que los docentes publiquen fragmentos de código, tareas o problemas relacionados con sus proyectos, en los cuales los estudiantes podrán colaborar de acuerdo con sus intereses, conocimientos y disponibilidad.

## ¿Qué problema busca resolver?

El proyecto busca facilitar el acceso de los estudiantes a experiencias prácticas de programación, ofreciendo una alternativa flexible para participar en proyectos reales o educativos sin asumir compromisos de larga duración.

De esta manera, se busca reducir las barreras para adquirir experiencia, aplicar los conocimientos aprendidos durante la formación académica y desarrollar habilidades relevantes para el ámbito laboral.

## ¿A quién está dirigido?

Bug-Hunter está dirigido principalmente a:

- **Estudiantes de DUOC UC:** que deseen fortalecer sus habilidades técnicas, colaborar en proyectos y adquirir experiencia práctica de manera flexible.
- **Docentes:** que necesiten apoyo en tareas de programación y quieran generar oportunidades de colaboración para sus estudiantes.

## Objetivo del proyecto

Facilitar la inserción temprana de los estudiantes al mundo laboral mediante una plataforma de colaboración remota y flexible, que les permita desarrollar sus competencias técnicas, adquirir experiencia y familiarizarse con dinámicas de trabajo similares a las del entorno profesional.

## Metodología de trabajo

El desarrollo de **Bug-Hunter** se organizará mediante una metodología ágil basada en Scrum, adaptada al tamaño del equipo y a los requerimientos del proyecto académico. El objetivo será avanzar de manera incremental, priorizar las funcionalidades principales y mantener una coordinación constante entre los integrantes.

### Planificación y gestión de tareas

Las funcionalidades y los requerimientos se dividirán en tareas específicas, priorizadas según su importancia para el producto. Cada tarea tendrá un objetivo definido y podrá ser asignada de acuerdo con los roles y responsabilidades de los integrantes.

### Desarrollo incremental

La plataforma se desarrollará por etapas, comenzando por las funcionalidades esenciales y avanzando progresivamente hacia características complementarias. El frontend y el backend se implementarán de forma coordinada, procurando mantener la compatibilidad entre ambos componentes.

### Control de versiones y colaboración

Se utilizará Git y GitHub para administrar el código fuente, registrar los cambios y facilitar la integración del trabajo de ambos integrantes. Se procurará trabajar mediante ramas independientes para las funcionalidades y utilizar *pull requests* para revisar e integrar los cambios cuando corresponda.

### Pruebas y validación

Se realizarán pruebas durante el desarrollo para verificar el funcionamiento de las funcionalidades implementadas, detectar errores y comprobar el cumplimiento de los requerimientos definidos. También se validará la integración entre el frontend, el backend y la base de datos.

### Seguimiento y mejora continua

El equipo revisará periódicamente el estado de las tareas, los avances obtenidos y las dificultades encontradas. A partir de estas revisiones, se ajustará la planificación cuando sea necesario, con el propósito de cumplir los objetivos y los plazos establecidos para el proyecto.

### Herramientas de trabajo

- **Git y GitHub:** control de versiones y colaboración en el código fuente.
- **PostgreSQL y Prisma ORM:** gestión y acceso a la base de datos.
- **Auth.js:** gestión de autenticación e integración con los proveedores definidos para el proyecto.
- **GitHub Projects u otra herramienta de seguimiento:** organización y monitoreo de las tareas, según las herramientas que finalmente utilice el equipo.
